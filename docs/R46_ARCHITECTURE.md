# R-46 Dot.Ehail transformation: architecture contract

Owner brief 2026-11-10 ("World-Class Mobility & Ride-Hailing Platform Transformation"), standing order: build everything, no questions, stop only after a successful deploy. This file is the contract every build agent codes against. Change it in the same commit as any deviation and log a decision in `docs/R46_DECISIONS.md`.

## 0. Constraints that shape everything
- Laravel 13 / PHP 8.4 on a shared cPanel host: no long-running processes (no Reverb/WebSocket server, no queue daemon; `queue:work --stop-when-empty` and `schedule:run` run from cron every minute). Production DB per `.env` (preflight reports it). Tests: SQLite in memory; a PostgreSQL suite is added.
- Therefore **real-time = short polling with versioned deltas** (passenger 3 s while a ride is active, driver 2 s while online, location posts every 4 s from a moving driver), with Laravel broadcasting events kept so Reverb works wherever it can run. **Dispatch progresses on demand**: every poll from a passenger or driver and the per-minute scheduler call `Dispatcher::tick()` for the affected rides, so offers expire and move on within seconds without a daemon. This is an honest, measurable design; the report states it.
- Money in integer minor units (`*_minor` bigint) with ISO currency; never floats. Existing decimal fare columns stay for history and are mirrored.
- Every external provider (routing, geocoding, map tiles, payments, payouts, SMS, push, email, emergency) is behind an interface with a config driver, timeouts, a circuit breaker and an honest "not configured / unavailable" state. No feature claims a capability whose provider is absent.

## 2. Ride lifecycle (dispatch owns; everyone codes to it)
States: `requested` (validated, quote locked) -> `searching` (offers in flight) -> `driver_assigned` -> `driver_arriving` -> `driver_arrived` -> `in_progress` -> `completed`. Terminal or side states: `cancelled_by_passenger`, `cancelled_by_driver` (returns to `searching` when policy allows, else terminal), `cancelled_by_operator`, `expired` (no driver found within the search window), `no_show` (driver waited the policy time at pickup), `failed` (system fault, e.g. payment impossible with no fallback), `needs_review` (stuck or disputed; ops only). Existing values map: `accepted -> driver_assigned`, `en_route -> driver_arriving`, `arrived -> driver_arrived` (data migration plus enum aliases for history). Scheduled rides start in `scheduled` and enter `requested` at the configured lead time. Every transition: row lock, guard (actor + preconditions), append to `ride_events`, dispatch a domain event (below), idempotent by transition key.
Domain events (plain Laravel events, also broadcastable): `RideRequested`, `DriverAssigned`, `DriverArriving`, `DriverArrived`, `TripStarted`, `TripCompleted`, `RideCancelled`, `RideExpired`, `RideNoShow`, `RideFailed`, `RideNeedsReview`. Payload: ride id + actor id + occurred_at + reason code.
Trip start requires the 4-digit ride PIN the passenger sees (configurable per market); a wrong PIN is rate-limited and logged.

## 4. Pricing model
`total = max(minimum, base + distance_rate x billable_km + time_rate x minutes + booking_fee + zone_fees + tolls + waiting) x demand_multiplier(if enabled, capped, shown; never applied to tolls, D-302) - promotions + taxes(if configured)`; every term configurable per rule set; rounding rule per currency (ZAR to whole rand optional). Quotes expire (default 5 min) and are bound to the passenger and route; the ride stores the quote id and the snapshot. Final fare rules: if actual billable distance/time differs from the quote by less than the configured tolerance, the quoted fare stands; above it, the fare is recalculated with the same rule version and the reason shown ("route changed at your request", "waiting time 6 min"); a fare never changes without a reason code; operators can adjust with an audited reason. Commission plans per market/fleet; driver earnings statement shows fare, commission, deductions, incentives, net.

## 7. Honest limits decided up front
- No in-house emergency dispatch: the SOS flow creates an incident, notifies trusted contacts and the operations team, shows South African emergency numbers (10111 police, 10177 ambulance, 112 from mobile) with one-tap call, and states exactly what was done. A third-party armed-response/medical integration is an owner decision.
- Turn-by-turn navigation is handed to the device's own maps app (Google Maps / Apple Maps / Waze deep links); Dot.Ehail shows the route, ETA and progress.
- Payouts: manual batch with export by default; automatic transfers only when the Paystack Transfers adapter is configured and the business is verified.
- Push notifications: Web Push (VAPID) where the browser supports it; SMS only with a configured provider.
- Background checks (criminal record) are not automated: document upload and manual review only.

## 8. Quality bars
Concurrency: a driver can never hold two active rides; a ride can never have two assigned drivers; a payment can never be captured twice; webhooks idempotent. Tests at every boundary; property tests for the state machine and pricing; a load test of 500 online drivers posting locations and 100 simultaneous requests on SQLite and PostgreSQL. No fake numbers anywhere in the UI.

## 9. Acceptance journeys (brief section 24)
Passenger, driver, safety and pricing journeys, including failure cases, are automated end to end in wave 3 (`tests/e2e/`).
