# R-46 decisions log

Append-only. `D-n (agent, date): decision. Why.` Keep both sides on merge conflicts.

D-1 (coordinator, 2026-11-10): Real-time is short polling with versioned deltas; broadcasting events stay for hosts that can run Reverb. Why: the shared cPanel host cannot run a WebSocket server (live /up/realtime is "degraded").
D-2 (coordinator, 2026-11-10): Dispatch advances on demand (every poll and the per-minute scheduler call Dispatcher::tick). Why: no daemons on the host; offers must still expire within seconds.
D-3 (coordinator, 2026-11-10): Money is integer minor units with ISO currency, versioned pricing rule sets, server-authoritative quotes with expiry. Why: brief section 6 pricing integrity.
D-4 (coordinator, 2026-11-10): Route-based fares require a real road route from a configured routing provider; straight-line distance is never billed. Why: brief section 10.
D-5 (coordinator, 2026-11-10): Turn-by-turn navigation hands off to the device's maps app; SOS creates an incident, notifies contacts and ops, offers SA emergency numbers; no claim of emergency dispatch. Why: honesty rules, no provider contracts.
D-500 (safety, 2026-11-10): verification_documents is a new table next to driver_documents (not columns on it); existing rows are carried over as pending with a link to the legacy row, files not copied. Why: driver_documents.type is an enum column (SQLite rebuild risk) and the old rows were never reviewed.
D-501 (safety, 2026-11-10): document types per market live in config/ehail_safety.php, not a table. Why: the list is a legal/ops decision changed rarely and deployed deliberately; a table needs an admin UI that is wave 2. Revisit if ops must edit at runtime.
D-502 (safety, 2026-11-10): DriverEligibility is an interface (App\Domain\Verification\DriverEligibility) bound to VerificationDriverEligibility; a DriverProfile::updating guard additionally refuses is_online false->true when the gate says no. Why: "never allow an unapproved driver online" must hold for the legacy toggle and any future path, not only dispatch. DriverOnlineToggleTest updated to use a verified driver (legitimate behaviour change).
D-503 (safety, 2026-11-10): fleet owners cannot open verification documents (owner, assigned reviewer, platform operators only). Why: identity documents are sensitive (POPIA minimisation); fleet owners keep the existing profile view.
D-504 (safety, 2026-11-10): images are re-encoded with GD (EXIF/GPS stripped, orientation applied, 2400 px / 40 MP caps); PDFs stored as uploaded; no virus scanning (none available on the host). Why: removes metadata and appended payloads with no dependency; the gap is documented.
D-505 (safety, 2026-11-10): trip-share tokens are 256-bit random values stored as SHA-256, not HMAC-signed URLs. Why: equally unguessable, revocable per link, and a database leak yields no working links.
D-506 (safety, 2026-11-10): /t/{token} runs without session, cookie and CSRF middleware. Why: brief requires no cookies for anonymous viewers.
D-507 (safety, 2026-11-10): SOS emails and SMS are sent inside the request (not queued) and each outcome is recorded in incident_notifications. Why: the queue runs once a minute from cron; an emergency alert cannot wait, and the confirmation screen must show real outcomes.
D-508 (safety, 2026-11-10): a mail transport of log/array is reported as not_delivered, never sent. Why: honesty rule; those transports deliver nothing.
D-509 (safety, 2026-11-10): SMS adapter is BulkSMS (JSON REST v1, Basic auth with API token). Why: public HTTP API, South African origin, simple; off by default. Clickatell can be added behind the same SmsGateway.
D-510 (safety, 2026-11-10): SOS is idempotent per (ride, person) while the incident is active via a unique idempotency_key released on resolve. Why: concurrent taps collapse at the database; both passenger and driver can each raise one.
D-511 (safety, 2026-11-10): escalation timers by severity (critical 2, high 5, medium 15, low 60 min), levels from env; past the last level all operators are reminded on the same timer; timers advance from the per-minute scheduler and from ops queue polls. Why: no daemon on the host.
D-512 (safety, 2026-11-10): check-in silence raises an incident for operations only; contacts are alerted only on "I need help" or SOS. Why: a phone in a pocket should not alarm a family.
D-513 (safety, 2026-11-10): incident_notifications, safety_check_ins and rating_appeals are added to the safety tables (architecture section 1 updated). Why: the "what we did" payload, check-in timers and one-appeal-per-rating need their own rows.
D-514 (safety, 2026-11-10): ride_ratings.moderated_by has no foreign key. Why: adding one on SQLite rebuilds the table and silently drops the 1-5 range triggers (caught by RideRatingTest).
D-515 (safety, 2026-11-10): bootstrap/app.php renders exceptions as JSON when the request expects JSON (in addition to api/*). Why: the R-46 JSON APIs live in web routes with session auth; without this, validation errors redirected JSON clients. One-line shared change; every wave-2 JSON client benefits.
D-516 (safety, 2026-11-10): RidePaymentStateTest's rollback step count is computed from the migrations table instead of a fixed 2. Why: any later migration (every R-46 agent adds some) broke the fixed count.
D-517 (safety, 2026-11-10): DriverStats excludes ratings with excluded_at (upheld appeals); DriverController's recent comments show only comment_status = visible. Why: moderation must take effect on existing surfaces.
D-518 (safety, 2026-11-10): passenger phone verification is reported as null (unknown), never true or false. Why: Dot.Ehail does not collect or verify phone numbers yet.
D-519 (safety, 2026-11-10): public safety pages use the control-room direction with system font stacks (IBM Plex named first, no webfont download). Why: DESIGN.md not yet written by ds; no CDN or third-party request from a page that must not track viewers. ds may restyle within its tokens.
