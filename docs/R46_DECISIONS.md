# R-46 decisions log

Append-only. `D-n (agent, date): decision. Why.` Keep both sides on merge conflicts.

D-1 (coordinator, 2026-11-10): Real-time is short polling with versioned deltas; broadcasting events stay for hosts that can run Reverb. Why: the shared cPanel host cannot run a WebSocket server (live /up/realtime is "degraded").
D-2 (coordinator, 2026-11-10): Dispatch advances on demand (every poll and the per-minute scheduler call Dispatcher::tick). Why: no daemons on the host; offers must still expire within seconds.
D-3 (coordinator, 2026-11-10): Money is integer minor units with ISO currency, versioned pricing rule sets, server-authoritative quotes with expiry. Why: brief section 6 pricing integrity.
D-4 (coordinator, 2026-11-10): Route-based fares require a real road route from a configured routing provider; straight-line distance is never billed. Why: brief section 10.
D-5 (coordinator, 2026-11-10): Turn-by-turn navigation hands off to the device's maps app; SOS creates an incident, notifies contacts and ops, offers SA emergency numbers; no claim of emergency dispatch. Why: honesty rules, no provider contracts.
D-200 (geo, 2026-11-10): Map engine is Leaflet 1.9.4 (BSD-2-Clause, pinned exact, new npm dependency) with raster tiles, lazy-loaded through a dynamic import. Why: measured map chunk 45.6 KB gzip JS + 2.6 KB CSS against a 150 KB budget; MapLibre GL JS 6.16.0 measured ~440 KB gzip (main + worker) and needs WebGL on low-end Android. No runtime CDN: Leaflet is bundled by Vite.
D-201 (geo, 2026-11-10): Default tiles are the OSMF tile server under its usage policy (visible attribution bottom right, "Report a map issue" link, Referer sent, keepBuffer 1, no prefetch, no service-worker tile cache, no offline). Why: the only no-key raster source whose policy does not forbid this use at launch scale; the policy warns access may be withdrawn for commercial services, so R46_GEO.md tells the owner to move to a contracted provider (one env change) before traffic grows.
D-202 (geo, 2026-11-10): Routing defaults to `none`. Booking shows "Route pricing is unavailable: the operator has not configured a routing provider" and no route fare is offered; straight-line distance is never billed. Why: no no-key routing service permits commercial fare quotes (OSRM demo: "reasonable, non-commercial use-cases" only); honesty rule and D-4.
D-203 (geo, 2026-11-10): Geocoding defaults to public Nominatim, search-on-submit only (no autocomplete), 1 request/s for the whole app enforced server-side, 24 h cache, identifying User-Agent, OSM attribution. Autocomplete turns on automatically with google, mapbox, ors or a self-hosted photon. Why: Nominatim's policy permits low-volume search and reverse but explicitly forbids autocomplete.
D-204 (geo, 2026-11-10): Provider drivers: routing google (Routes API computeRoutes, traffic-unaware Essentials), mapbox (Directions v5), ors (Directions v2), osrm (URL), valhalla (URL, precision-6 shapes re-encoded to 5), none; geocoding google (Places Text Search + Geocoding API reverse), mapbox (Geocoding v6), ors (Pelias), photon (URL), nominatim (URL), none. Keys only on the server; the browser calls /geo/*. Google and Mapbox answers are not cached by default (their terms restrict storing results).
D-205 (geo, 2026-11-10): Route cache is a database table (`route_cache`) keyed by provider + profile + toll option + coordinates rounded to 4 decimals (~11 m), TTL 10 min; circuit breaker in the application cache (5 failures / 60 s opens for 60 s); 4 s timeouts. Why: shared host, no Redis guaranteed; identical quote requests are common while a passenger compares categories.
D-206 (geo, 2026-11-10): Added a geo-owned table `ride_routes` (planned polyline per ride + distance summary kept after trail purge). Why: deviation needs the route the passenger agreed to, and retention must keep a distance record after raw points are deleted; `rides` belongs to dispatch. Architecture section 1 updated.
D-207 (geo, 2026-11-10): No PostGIS. Nearby drivers = bbox on indexed lat/lng + exact haversine in PHP; zones = JSON polygon + stored bbox + ray casting. Why: host availability and SQLite tests; adequate for 500 online drivers.
D-208 (geo, 2026-11-10): Location ingest accepts 1..20 samples per post (dead-zone queue), throttled to one post per driver per 2 s; per-sample screening (accuracy > 150 m, > 30 s future, > 10 min old, out of order, > 70 m/s jump unless three agree). Only fixes <= 60 s old move the latest row; trip points only while the ride is in_progress (approach to pickup is not part of the trail), at most one per 3 s / 25 m. Why: honest positions for matching, and a trail for billing without storing more than needed.
D-209 (geo, 2026-11-10): Retention: trip points 90 days then summarised onto ride_routes and deleted (daily 02:40, `ehail:geo-purge`, scheduled from EhailGeoServiceProvider so routes/console.php is untouched), driver latest rows deleted after 7 days of silence, passenger live position never stored. Safety can hold a ride's trail through the `TrailRetentionHold` seam. Why: POPIA minimality.
D-210 (geo, 2026-11-10): Privacy: a passenger reads only their assigned driver's position, only while the ride is active (403 with a reason otherwise); non-parties get 404; operators may read. Why: POPIA purpose limitation; existence of other rides is not revealed.
D-211 (geo, 2026-11-10): Billable distance bridges GPS gaps (> 45 s and > 400 m) with a road route when routing is configured; otherwise the gap stays a straight line (passenger-favourable), flagged `unresolved_gap` / quality `degraded` so pricing keeps the quote. Why: never bill straight-line as if it were the road, never invent distance.
D-212 (geo, 2026-11-10): Deviation = 3 consecutive good samples more than 300 m (+ accuracy) from the planned route; unusual stop = stationary within 40 m for 5 min away from the drop-off (200 m). Fix: the lock expires after 10 minutes, and `ehail:settlement-sweep` (every five minutes) re-queues completed rides with a fare due (`payment_status` unpaid) that have neither a trip earning nor a fare charge 15 minutes after completion (lookback 7 days, `money.settlement_sweep.*`), releasing a stale lock first, raising a critical `settlement_missing` finance issue (ops finance exceptions list) and logging `ehail.settlement_missing`. Each settlement run logs `ehail.settlement` with its outcome. Why: money must never be silently uncollected, whatever loses the job.
