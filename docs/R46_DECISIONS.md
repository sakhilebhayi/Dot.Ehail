# R-46 decisions log

Append-only. `D-n (agent, date): decision. Why.` Keep both sides on merge conflicts.

D-1 (coordinator, 2026-11-10): Real-time is short polling with versioned deltas; broadcasting events stay for hosts that can run Reverb. Why: the shared cPanel host cannot run a WebSocket server (live /up/realtime is "degraded").
D-2 (coordinator, 2026-11-10): Dispatch advances on demand (every poll and the per-minute scheduler call Dispatcher::tick). Why: no daemons on the host; offers must still expire within seconds.
D-3 (coordinator, 2026-11-10): Money is integer minor units with ISO currency, versioned pricing rule sets, server-authoritative quotes with expiry. Why: brief section 6 pricing integrity.
D-4 (coordinator, 2026-11-10): Route-based fares require a real road route from a configured routing provider; straight-line distance is never billed. Why: brief section 10.
D-5 (coordinator, 2026-11-10): Turn-by-turn navigation hands off to the device's maps app; SOS creates an incident, notifies contacts and ops, offers SA emergency numbers; no claim of emergency dispatch. Why: honesty rules, no provider contracts.
D-400 (dispatch, 2026-11-10): State machine v2 lives in one edge table (App\Domain\Rides\RideTransitions) executed only by RideStateMachine; RideStatus::allowedTransitions() reads it. Why: one place to review what may follow what, guards and effects named per edge.
D-401 (dispatch, 2026-11-10): Pre-v2 'cancelled' rows split by who cancelled: cancelled_by = passenger_id -> cancelled_by_passenger, otherwise cancelled_by_operator; RideStatus::LEGACY_ALIASES keeps the old values readable. Why: before v2 only the passenger or an operator could reach 'cancelled'; operator is the conservative reading of an unknown canceller.
D-402 (dispatch, 2026-11-10): "One active ride per driver/passenger" is enforced with nullable unique columns (rides.active_driver_id, rides.active_passenger_id, driver_availability.current_ride_id, ride_offers.pending_*), not engine-specific partial indexes. Why: every engine allows many NULLs in a unique index, so the same DDL guards SQLite, PostgreSQL and MySQL (production per .env.example is PostgreSQL; MySQL has no partial indexes).
D-403 (dispatch, 2026-11-10): Exhausted reassignments end as cancelled_by_driver (was expired) and the ride no longer shows a driver; the passenger notice and Dot.Notify ride.expired email are kept as before. Why: architecture section 2; avoids changing the email contract with Dot.Notify.
D-404 (dispatch, 2026-11-10): Sequential single-driver offers (15 s) ranked by pickup ETA plus capped, logged fairness terms (idle credit, trip balance, temporary decline cooldown); no batched global matching yet. Why: launch volume and no daemon (D-1/D-2); research in docs/R46_RESEARCH.md.
D-405 (dispatch, 2026-11-10): The pre-R-46 claim queue stays as an "open board" fallback after 45 s of searching (configurable, negative disables). Why: keeps the existing driver page useful when sequential offers fail, without making fastest-finger the primary mechanism.
D-406 (dispatch, 2026-11-10): Dispatch keeps the latest driver position on driver_availability (one row per driver, overwritten, stored only while not offline) as its search index; trails and retention belong to geo, reached through the DriverLocationSink seam. Why: a working default DriverLocator before geo merges; POPIA minimisation.
D-407 (dispatch, 2026-11-10): Every cross-domain dependency is a dispatch-owned contract bound with bindIf to an honest default (App\Domain\Dispatch\Contracts\*): FareQuoteGateway (503 until pricing binds it), TripFareFinaliser (agreed fare), CancellationFees (none), DriverEarningsEstimator (null), CategoryEligibility (config vehicle_tiers), DriverLocator, PickupEtaEstimator (straight-line, ranking only), ServiceAreaCheck (unknown), DriverLocationSink (none), DriverEligibility (profile approval), PaymentMethodResolver (cash only). Why: parallel build; other owners bind their implementation without editing dispatch files.
D-408 (dispatch, 2026-11-10): Feed versions are epoch microseconds in integer columns (rides.version, driver_availability.version/location_version, ride_offers.version). Why: timestamp columns keep second precision; microseconds make a missed change practically impossible and stay inside JavaScript's exact integer range.
D-409 (dispatch, 2026-11-10): The dispatch JSON API is mounted under /api/ehail/... inside the web (session) route group. Why: bootstrap/app.php renders JSON errors only for api/*; wave-2 UIs call it with the session cookie and CSRF token.
D-410 (dispatch, 2026-11-10): Trip PIN = 4 digits; HMAC (APP_KEY, salted with the ride id) for checking plus an encrypted copy shown only to the passenger; 5 wrong entries lock it 10 minutes, each audited; rides without a PIN (pre-R-46) start without one. Why: a 4-digit hash alone protects nothing, the attempt limit does; existing rides keep working.
D-411 (dispatch, 2026-11-10): Scheduled rides are allocated 15 minutes before pickup (no driver reserved earlier); the booked fare is honoured within 10% of a fresh quote or when pricing cannot quote, otherwise the passenger must accept the new fare. Why: honest "awaiting driver" vs "driver confirmed"; price guarantee is configurable.
D-412 (dispatch, 2026-11-10): Transactions in the dispatch domain retry 3 times on lock contention; the API maps a leftover concurrency error to 409 conflict_retry. For any SQLite deployment the recommended connection settings are transaction_mode IMMEDIATE, busy_timeout 10000, journal_mode wal (not changed in config/database.php, a shared file). Why: measured in ConcurrencyTest with forked processes.
D-413 (dispatch, 2026-11-10): No new dependencies. Why: none needed.
